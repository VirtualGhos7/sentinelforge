# SentinelForge development rules

- All assets, changes, identities and incidents in demonstrations are fictional.
- Never scan targets or execute system commands from agent tools.
- Enforce permissions, resource scopes and approval consumption outside models.
- Verification reads simulated state independently; executor success cannot close cases.
- Preserve evidence and append audit events. Document database administrator tampering limitations.
- Run pytest and frontend checks before publication. Record actual outcomes, not expectations.
- No secrets, local paths, private interview preparation or runtime databases in Git.
- Prefer a modular monolith. Keep offline mode explicit; never claim live AI results without execution.
